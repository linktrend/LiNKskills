# Economic, earnings, and cross-asset event calendar successor proposal v0.1.1

Status: isolated source-completion proposal for owner review; not canonical or behavior-qualified. Scope: approved group 3, “Economic, earnings and cross-asset event calendars.” This method returns a dated, source-linked calendar from user-supplied or individually verified authorized sources. Provider retrieval is a separate conditional branch; this artifact does not establish access, terms, key possession, current endpoint behavior, or data rights.

## Input contract

Required: requested inclusive date window (or explicit relative period resolved to exact dates at execution), timezone for presentation, target countries/markets/currencies and event classes, as-of timestamp, source records or declared source-collection capability, and requested output granularity. Every source record must include publisher/issuer, exact document/page/API response identity, retrieval/publication timestamp, source timezone if known, license/access status where available, and supplied raw event fields. Each event has name/type, country or market, scheduled date and time (or `time_tba`), original timezone or explicit timezone-unknown, source, source timestamp, status (`scheduled`, `time_tba`, `postponed`, `cancelled`, `released`, `revised`), actual/previous/estimate only when supplied, currency/unit and period, revision history, and stable source event identifier if available. Optional inputs: holdings/watchlist and exposure mapping, release calendar, earnings event schedule, central-bank agenda, macro releases, options/implied move data, and scenario sensitivities. Missing source access is a valid state; it must not be interpreted as an empty calendar.

## Output contract

Produce chronological event rows with local presentation time and original source time, event category, country/currency, state, forecast/previous/actual with units and period where available, source pointer, last-checked time, and source freshness/coverage. Group same-date clusters without merging individual events. Report exact window/timezone, sources actually reviewed, unsupported source families, duplicates/reschedules, TBA/cancelled events, and known coverage gaps. If supplied positions justify it, add an exposure/watch relevance note linked to the instrument and reason; do not fabricate an impact score. Missing time or source returns `time_tba` / `source_unknown`, not a guessed event time. Empty rows means “no events found in the reviewed sources for this scope,” not “no events exist,” unless sources affirm complete coverage.

## Integrated method

1. **Resolve scope and time basis.** Convert “next week,” “this month,” or similar to explicit start/end dates using the current local date only when available, preserve inclusive boundary rules, and name the calendar timezone. Record target geography, assets, event families, and whether past actuals or upcoming events are wanted. Reject invalid or inverted dates. Split requests larger than an individual source’s published limit only if the source contract permits; otherwise report the uncovered window. Never infer a source time zone from the country label.

2. **Build collection coverage before event rows.** Enumerate source classes needed for the request: official statistical agency releases; central-bank decisions/speeches; issuer investor-relations earnings dates; exchange/market holidays; supplied cross-asset catalysts such as auctions, expiries, index events, or scheduled policy votes. For each, record source and checked-at timestamp, window covered, and collection status. Prefer primary official calendars for dates and issuer IR for earnings. A secondary aggregator can supplement but does not override a conflicting primary record without an explicit discrepancy row. If the requested source class could not be checked, emit a coverage gap even when other events were found.

3. **Normalize event identity and time.** Preserve original timestamp/timezone and derive display time using an explicit IANA timezone conversion, including daylight-saving rules. If source timestamp lacks zone and no source documentation establishes it, keep wall time and mark zone unknown; do not convert. Maintain source event ID; otherwise use a provisional key from publisher, event family/name, geography, reference period and original scheduled date. A revised time/status is a new version of the same event, with prior value retained. Do not collapse distinct releases with similar names. Show which event is controlling for the display window and retain contradictory source rows.

4. **Preserve schedule state and data lineage.** Keep `time_tba`, `postponed`, `cancelled`, and `released/revised` as explicit states. Actual/previous/estimate values are not interchangeable; preserve the value’s unit, period, publication time and revision vintage. A later revised “previous” value does not overwrite the originally published value. For earnings, identify issuer and fiscal period; do not infer the quarter from calendar date. For macro, distinguish preliminary/final/second estimates when supplied. Empty aggregator response, inaccessible page, or API error is `coverage_unavailable`, never zero events.

5. **Optional specialist event branches.** Keep these as independently scoped workstreams in addition to the calendar rows; do not invent a specialized analysis when the user only asked for dates.
   - **Earnings-event brief:** identify issuer, fiscal period, event date/time and horizon; record release/filing/prior results/guidance, dated estimate revisions, price/volume/realized-volatility/peer context and options-implied move only when actually supplied. Build bull/base/bear conditions and a post-event interpretation checklist. Never equate options-implied move with directional probability. Missing estimates/options permits fundamentals-and-price-only output with named omissions.
   - **M&A milestone tracker:** require announcement/definitive agreement, parties, consideration type, offer price, current target price and timestamp, expected close if stated, termination conditions, filings/proxy/merger agreement, vote date and regulatory jurisdictions/milestones. For an all-cash offer `C` and current target price `P`, gross spread/share is `C−P`; gross spread return is `(C−P)/P` only if `P>0`, before financing, fees, borrow, close timing and break risk. For fixed stock ratio `r` plus cash `c`, mark-to-market consideration is `r × current_acquirer_price + c`, with both security prices timestamped and in compatible currencies; convert only using supplied dated FX. For collars/contingent terms or no current price, do not simplify the contract: give a dated milestone timeline and missing-input list without spread/probability. Break-risk rows cover financing, antitrust/regulatory, shareholder vote, litigation, macro and acquirer-stock consideration; do not invent legal deadlines or approval probabilities.
   - **Regulatory/policy risk monitor:** identify regulator, jurisdiction, asset/company, rule/docket/filing, decision window, company exposure via sourced revenue/cost/capital/supply/license pathway, relevant news/market data, and an event timeline. If docket/calendar access is missing, produce a risk map marked partial; do not infer outcomes from political preference or provide legal advice. A probability range is permitted only with an identified, resolved-outcome evidence/calibration basis; otherwise use qualitative scenarios.

   For all three, if current market/options/peer/news data are absent, state the relevant branch unavailable; do not substitute a stale aggregator or implied narrative. Any second-source review must be an actual independent review, not an asserted agent invocation.

6. **Optional impact/relevance analysis.** First identify exposure only from a supplied holdings/watchlist with instrument, currency and as-of. Map a catalyst to a holding only when a defensible instrument/economic linkage exists and label the link as direct, indirect, or speculative. A sourced estimate-vs-previous comparison can show anticipated change, but not surprise until the actual release; if consensus timestamp or units are missing, suppress the comparison. Do not assign high/medium/low impact from an aggregator label as Jane’s independent conclusion. If requested, produce a transparent qualitative attention ranking with the stated rationale, evidence, and countercase; no causal price move, fixed thresholds, or calibrated probability without supporting data.

7. **Generate and audit.** Sort by derived local date/time, with undetermined time grouped before/after dated items explicitly rather than assigned an arbitrary clock time. Keep simultaneous events separate. Include “last checked” per source and identify unresolved date/time/country conflicts. Verify every row’s source pointer and timezone transform, recheck inclusive start/end boundaries, retain revisions, and state whether coverage is complete only for named source classes. If the task is an upcoming calendar, future actuals remain null/absent; do not forecast them.

8. **Conditional FMP branch (not enabled by this proposal).** The pinned economic-calendar fetcher defines an API/script workflow with requested `from`/`to` dates, response fields, post-fetch filters and assistant-generated Markdown, but the current service contract, entitlement, terms and credential availability are not verified here. Its script places the API key in a query parameter; any future adapter must keep credentials outside prompts, command arguments, returned URLs, error text and logs, redact request URLs, and use an approved credential handle. Input must include exact requested window, country/event filters, endpoint/version and retrieval timestamp. Output must preserve response/error status, actual coverage, source fields and request identity; then run steps 3–7 and record API provenance. A key failure, restricted endpoint, rate limit, network error or empty-but-unverified result becomes `coverage_unavailable` or `response_empty_unconfirmed`, not “no events.” Do not use a legacy endpoint or run the quarantined upstream script. No API call is made by this artifact.

## Focused expectations

- Event at 00:30 UTC on the preceding local date: include/exclude by converted local date while preserving UTC and inclusive boundaries.
- Local DST transition with ambiguous/nonexistent time: preserve source time and mark conversion ambiguity; do not shift by guess.
- Same event revised from 14:00 to 15:00: show current time and revision history; do not duplicate as two active events or erase original.
- Earnings aggregator gives date only: state time unknown; do not assume before-market or after-close.
- Provider returns empty response but source coverage/error contract unavailable: no “no events” conclusion.
- Secondary calendar conflicts with official agency date: expose both with primary-source discrepancy and unresolved status.
- Event estimate is a percentage but actual is an index-point value: suppress surprise math.
- User asks which events could affect a portfolio but supplies no holdings: provide event calendar only; exposure relevance unavailable.
