# Market news, reaction, social sentiment, and event intelligence: successor proposal v0.1.1

Status: isolated source-completion proposal, not canonical, enabled, or qualified. It replaces six generic placeholders in the frozen skill only as a successor candidate. Approved group 4 requires news, market reaction, social sentiment and event intelligence. The current structured qualitative report is useful for user-supplied source material but does not close the full original breadth: automated current-news collection, explicitly sampled social evidence, corporate event impact and geopolitical/commodity channels remain separately gated.

## Task input and output

Inputs: question, assets/universe, event types, requested observation window/timezone, cutoff/as-of; supplied or accessible news with publisher, author if available, publication/event/update times, URL/document identity, exact claim and source rights; price/volume/benchmark series with venue, currency, session/calendar, adjustment and source timestamps; corporate filings/releases for confirmation; commodity contract/benchmark, venue, location and FX basis where relevant; social platform/source, terms/access permission, query/frame, collection timestamp, inclusion rules and sample metadata. Unknown data remain unknown.

Output: event ledger with one row per deduplicated event/claim; source tier and corroboration; fact/claim/opinion split; publication versus event time; affected issuer/assets and causal-channel hypothesis; benchmark-relative price/volume reaction over explicit event windows when valid price data exist; alternate explanations/confounders; social sample result and scope limitations when authorized evidence exists; unresolved facts, stale/missing inputs and confidence rationale. Label causal linkage as hypothesis absent a designed identification strategy. Never turn sample sentiment into population opinion or market correlation into causation.

## Integrated task method

1. **Frame and collect with bounded coverage.** Set a user-stated window, asset list, language, event types, timezone and cutoff. Search only through a currently available, authorized interface or use user-provided documents. Record the actual queries/sources/time covered and failed or inaccessible branches. The pinned TraderMonty primary describes last-10-day automatic WebSearch/WebFetch retrieval; ten days is not a universal default and those tools/data terms are not proven here. If no current search tool is actually exposed, return source retrieval as blocked and analyze only attached/user-supplied material.

2. **Normalize claims and event identity.** Separate event time, first publication time, revisions/correction time and market session. Deduplicate syndicated/reposted articles while retaining original and revision links. Split a report into atomic claims; label each as company/regulator filing, named source quotation, journalist-reported, analyst inference, social statement or unknown. Confirm material corporate facts against an official filing/release when supplied/access is authorized. Conflicting sources are recorded together; do not average them into a false consensus.

3. **Classify event type and expected channel.** Use source labels (for example, earnings/guidance, capital action, legal/regulatory, product/operations, M&A, management, macro/policy, geopolitical/supply-chain) as a controlled taxonomy with an explicit “other/unknown.” State why the event could affect revenue, costs, discount rates, supply, demand, risk premium or sentiment. A channel is a testable mechanism, not proof. For geopolitical/commodity effects, name the commodity contract or physical benchmark, delivery location, supply/demand/transport exposure, affected firm/industry, FX and relevant calendar session; if these mappings are absent, report a plausible scenario only.

4. **Measure reaction only against supplied, comparable observations.** Identify last unaffected close, event/announcement timestamp and first tradable session; state reaction windows and return convention. For a matched price/total-return series, calculate asset return r_a = (value_end/value_start) − 1 and benchmark return r_b over the same event window/sessions; define arithmetic relative return as r_a − r_b in percentage points and identify split/dividend/FX conventions. Show absolute and benchmark-relative results and volume basis separately. Distinguish pre-market/after-hours from regular-session prints. Do not treat a selected window’s move as causal; list concurrent earnings, macro releases, flows, corporate actions, market-wide moves or data-quality issues. If event timestamp/price source/benchmark is missing or incompatible, retain narrative and mark reaction not measurable.

5. **Social sample method.** Treat public posts as a bounded, nonrepresentative sample. Before collection, declare platform, permitted access/terms, query/keywords, language, start/end, retrieval time, sort/selection method, inclusion/exclusion and dedup rules. Report counts of retrieved, unique, on-topic and excluded posts, source mix and whether author/bot/brigading checks were possible. Preserve examples only when permitted and minimize personal data. Separate sentiment polarity/stance from factual corroboration, sarcasm, jokes, reposts and promotional/coordination signals. Do not publish a numeric population sentiment or infer market-wide positioning from an opaque API sample. Without frame and permission, social analysis is unavailable; never substitute a scraped or paid feed by assumption.

6. **Rank and communicate.** If the user wants ordering, sort by stated exposure/relevance, event time, evidence strength and measured reaction; disclose the basis rather than invent a universal impact score. Summarize evidence for/against each channel, alternative causes, what observation would revise the view and the next timestamp to monitor. No automatic exposure/action bands.
