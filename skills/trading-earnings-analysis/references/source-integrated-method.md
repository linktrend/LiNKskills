# Earnings preview, results, and estimate-change method successor proposal v0.1.1

Status: isolated source-completion proposal for owner review; not canonical, not behavior-qualified, and not a promise of document or data-tool availability. Scope: approved group 2, “Earnings previews, results analysis and estimate changes.” It covers pre-event setup, post-release analysis, and later estimate-change monitoring. The upstream 8–12 page / 3,000–5,000 word / 8–12 chart format is one institutional template, not a Jane output quota. Deliver the requested concise evidence report by default; make DOCX, model workbook, or rendered charts only when the relevant approved tool is actually available and requested.

## Task input contract

Require: issuer/legal name and ticker/share class; requested mode (`preview`, `results`, `estimate_change`, or combined); fiscal quarter/year and fiscal-calendar definition; as-of timestamp and timezone; report currency; authorized source records with exact URL/document identifier, publication/filed timestamp, period, page/table/line when available, and whether the source is primary, consensus, transcript, company guidance, or market-price series. Each numeric observation needs metric name, value, unit/currency, GAAP/adjusted definition, actual/estimate/guidance status, fiscal period, source pointer, and source timestamp. Estimates require provider/consensus-vintage ID and snapshot time strictly before the release for surprise comparisons. Company guidance requires period and range/point/range definition. Include prior-quarter and prior-year comparison values only when their definitions align. Optional inputs: prior Jane thesis/model assumptions, segment/product/geography data, transcript or webcast notes with access rights, price/benchmark total-return observations, valuation method/assumptions, existing position/constraints, and requested deliverable format.

Missing sources or fields are valid input states: represent them as absent with a reason (`not_published`, `not_supplied`, `not_accessible`, `not_comparable`, `rights_unverified`, `not_applicable`). Never substitute a search result snippet, stale training knowledge, a post-release consensus snapshot, or an assumed transcript. Do not require a transcript when none is available; mark management-commentary analysis partial. Do not assert that current-quarter results are the latest unless current source research established the release and quarter. No market-data, consensus-vendor, transcript, DOCX, spreadsheet, or chart tool is implied by this method.

## Output contract

Return a dated report with issuer, mode, quarter, as-of time, source-coverage table, and one row per result/estimate/guidance metric. Each row contains actual/estimate or old/new values, units and definitions, period, source pointers, calculation, denominator where used, status, and caveat. Separate observed facts from interpretation and proposals. Include: summary of what changed; beat/miss only where a comparable pre-release estimate exists; operational/segment drivers when sourced; guidance and estimate revisions; thesis/risk changes; optional valuation/rating/target proposal with assumptions; event-reaction comparison only when aligned data exist; and missing-input/source-rights list. Every key number and every generated table/chart has a source pointer. If a table/chart file cannot be generated, provide a textual series specification and say `not_generated`.

Use statuses `complete_from_supplied_evidence`, `partial_named_missing_items`, `unavailable_missing_basis`, or `not_requested` at each branch. An unavailable branch does not suppress independent findings. No causal claim from temporal sequence or a single earnings reaction. Jane may recommend raising/lowering estimates, thesis, rating, target, or a position increase/trim/exit when evidence and supplied constraints justify it. These are proposals only; no order, signing, live activation, or policy mutation. Any material/live/capital change requires Lisa and Carlos independent approval channels for the exact version.

## Integrated method

1. **Choose event mode and freeze the comparison basis.** Record issuer, fiscal period, release date/time, pre-market/after-close status if known, time zone, and mode. Establish the company fiscal calendar from a cited filing or release; do not map “Q2” to calendar quarters by default. For `preview`, use the latest authorized pre-event company materials and timestamp each estimate. For `results`, identify the actual release and matching filing/transcript period. For `estimate_change`, compare two dated snapshots of the same metric and period. If a required event date or period cannot be established, preserve the unresolved identity and do not compare mismatched quarters.

2. **Build the evidence ledger.** Collect, where supplied/accessible: earnings release; same-period 10-Q/10-K; investor presentation/supplemental data; prior-quarter guidance; pre-event consensus snapshot; transcript/webcast notes; previous estimate/model; comparable price and benchmark series. Record publication vs observation timestamp separately. Transcript must match the release period and date (allow a documented publication lag); filing must be the same fiscal period even if filed later. Preserve management statements as paraphrases with source pointer, or short attributed excerpts only when the access terms permit. Mark source coverage and dates. The upstream workflow emphasizes current-quarter identification, actual source documents, matching periods and pre-release consensus; this method adopts those checks, not its rigid “within three months” calendar cutoff, word/page counts, or subscription-source assumptions.

3. **Normalize before comparing.** For every metric align period, currency, units, GAAP/non-GAAP basis, continuing/discontinued operations, share count/dilution basis, and segment definition. Keep reported and adjusted EPS separate. If currency conversion is needed, require rate, source, timestamp, and conversion convention; otherwise report values in native currency and mark cross-currency comparison unavailable. Never compare actual GAAP EPS against adjusted consensus as if like-for-like. A later restatement/revision creates a separate observation, not silent replacement.

4. **Quantify surprise and revisions.** For actual `A` and consensus `C` for the same metric/period/basis, signed absolute surprise is `A − C` in the metric’s native unit. Surprise percent is `(A − C) / abs(C) × 100` only when `C != 0`; otherwise the percent is undefined while the absolute difference remains. Label EPS, revenue, margin, volume and per-share units. A consensus snapshot after the release cannot establish beat/miss. Compare current guidance with previous guidance only for the same fiscal period and measure. If guidance is a range with endpoints `L,U`, midpoint is `(L+U)/2`; midpoint change is new minus old, and percent change divides by `abs(old_midpoint)` only if nonzero. If range definitions differ, endpoints or periods are missing, do not calculate a midpoint change. Consensus revisions require two dated snapshots for the same forecast period, measure, basis and provider/aggregation definition; report each value and vintage before calculating new minus old.

5. **Explain drivers, not just direction.** Summarize revenue, EPS, margins, cash flow, segment/geography/product metrics and operating indicators only if supported. For each material beat/miss or revision, separate arithmetic contribution from explanatory evidence: price vs volume/mix, FX, acquisitions/disposals, timing, one-offs, demand, costs, supply, and management outlook. Label each driver `reported`, `management_attributed`, `analyst_inference`, or `unknown`. Compare QoQ and YoY only with fiscal periods and definitions stated. Include analyst questions and management answers only from an accessible, correctly matched transcript or webcast notes. Missing transcript means no invented tone/consensus narrative.

6. **Preview-specific scenario and catalyst branch.** For preview requests, return a company-specific watch list (metric, current baseline, sourced consensus/range, why it matters, source and measurement period) plus bull/base/bear scenario rows. Scenario rows state conditions, metric ranges only where input assumptions support them, management evidence that would confirm/refute, and directional implications. A stock-price target or reaction estimate requires explicit valuation/price assumptions and comparable history; otherwise mark it qualitative/unavailable. Options-implied move requires supplied options inputs with expiry/strike/volatility convention and is labeled as market pricing, not forecast. Historical reaction comparisons use matched earnings windows and adjusted total-return series; avoid selecting only favorable events.

7. **Update estimates, thesis and valuation after results.** Show old estimate → new estimate → change and the driver/source for each changed line; retain unchanged values and explicitly note unsupported lines. Update the thesis by listing claim, new evidence, counterevidence, and whether it changes conviction or invalidates a premise. If an existing valuation model and inputs are supplied, state method, forecast horizon, discount rate/multiples, terminal assumptions, share count, net debt and sensitivity; use the same units/currency. Price target/rating/position proposal is conditional on that work and risk constraints. If an input is missing, present a scenario range or withhold target rather than fill a standard template with invented precision. Report management guidance as a range and compare with the prior range and pre-release consensus separately.

8. **Optional market-reaction branch.** With split/dividend-adjusted total-return observations on an explicitly stated event window, calculate asset return as `end_value/start_value − 1` and benchmark return identically. Arithmetic relative return is asset return minus benchmark return in percentage points. Report start/end timestamps, trading sessions, currency, adjustment/source and benchmark. A raw price change is not total return. The calculation describes an observed window; it does not show that earnings caused the move. If event alignment or either return series is absent, mark this branch unavailable.

9. **Compose requested deliverable and quality-check.** Default to a concise source-linked report: executive finding; evidence coverage; results/consensus table; segment/driver analysis; guidance and estimates; thesis/risk/valuation implications; source list; unknowns. A user may request a fuller DOCX/report. If actual document/chart capability is available, follow a clear summary → results → metrics/guidance → thesis/valuation → appendix progression; use a small set of useful summary tables and charts drawn from supplied time series. Charts need title, axes, units, period, source/as-of and visible missing periods. Do not promise page counts. Before delivery reconcile every table number against its ledger, verify all source pointers resolve to supplied evidence, ensure estimate timestamps precede release, ensure arithmetic and units, label not-generated artifacts, and disclose delayed/incomplete source collection. The upstream `report-structure.md` and `best-practices.md` contribute these structure/citation/QA needs; they do not make DOCX rendering or hyperlink validation available here.

## Adversarial cases and expected conclusions

- EPS actual is adjusted USD/share; consensus is GAAP USD/share: no beat/miss; report mismatch and separate values.
- Consensus timestamp is after the release: reject as a pre-release estimate; beat/miss unavailable.
- Consensus equals zero: absolute surprise valid; percent surprise undefined.
- Guidance old and new ranges refer to different fiscal years or currencies: no midpoint change; mark non-comparable.
- Transcript names a different quarter or is unavailable: omit commentary claims; results analysis can remain partial.
- Release, filing, and fiscal calendar disagree: halt cross-document merge; report period identity unresolved.
- Metric actual is revised in a later filing: retain original and revised records with timestamps; state which basis each conclusion uses.
- All supporting materials are present but no chart tool is exposed: provide series/chart specifications only, status `not_generated`.
- Price rises after earnings but there is no aligned benchmark or event window: do not infer causal impact or relative outperformance.
