# Known failure patterns

- Importing the upstream source's framework list or script output as current applicability evidence.
- Treating a requested framework or certification objective as legally required without cited source and company facts.
- Treating a candidate evidence mapping as accepted evidence reuse.
- Reusing the source's numerical mock-audit thresholds as a company policy or readiness rule.
- Treating calendar titles or assigned auditor roles as proof of independence.
- Presenting an advisory option as an approved commitment, calendar, policy, audit result, or certification sign-off.
- Assuming a preserved upstream script/API is callable by Sara.
- Turning absent records into a clean result instead of `unknown` or `needs_context`.
- Creating local JSONL or JSON runtime state instead of using supported consumer-owned persistence.
