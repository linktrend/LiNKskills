# sop-authoring — method selection and source boundaries

Same task: author an executable controlled SOP. OneWave is the strongest base for gap interviews and reader usability; incorporate Anthropic's observed-process discovery, RACI, metrics and review structure. Distinct diagnostic/runbook work remains separate.

## Integrated task controls

1. Use the supplied approved library template, heading/version/naming conventions; record purpose, process owner, audience, trigger, prerequisites and observed evidence. If none is supplied, label the proposed format as a draft.
2. Extract the actual process from records or walkthroughs. For every usually, unless, it depends or ask someone branch, ask a targeted gap question about criteria, owner and escalation; mark unresolved actions [TO CONFIRM] rather than invent an answer.
3. Write one concrete action per numbered step with actor, input, actual interface, output and check. Specify decision thresholds, exception handoffs, approvals, stop conditions and recovery; keep current practice separate from proposed improvements.
4. Include required forms, screenshots/placeholders, RACI, records, metrics and authorized retention/access references. Put fragility and suggested improvements in a separate risk note, not silently into the as-is SOP.
5. Pressure-test the draft as a new operator with no prior context using one normal case and one ambiguous exception. Identify each point requiring unstated judgment; repair or mark [TO CONFIRM], retain evidence and obtain the designated controlled-version approval.

Source scripts remain copied evidence and are not automatically trusted executable tools. Read individual supporting assets when required; use granted native tools for actual work.
