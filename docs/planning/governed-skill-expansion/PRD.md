# LiNKskills Governed Skill Expansion — Final PRD

## 1. Outcome

LiNKskills becomes the sole governed provider of reusable agent skills, workflows, procedures, reasoning methods, best practices, and role/domain capability packs. Authorized consumers progressively discover qualified capabilities, retrieve an immutable exact release, verify it, and execute it locally through separately authorized tools. LiNKskills never grants credentials, technical permissions, business authority, or permission to act.

The delivery has four product outcomes:

1. complete the real provider-v2 progressive discovery and exact-resource path;
2. add one reusable external-collection lifecycle and admit the complete reviewed Google Workspace collection without automatic activation;
3. qualify the approved shared methods and Lisa-canary skill families without private instance data; and
4. fill the nine approved business families and publish reusable role-pack manifests for future agents without launching them.

## 4. Provider and discovery requirements

### 4.1 One progressive hierarchy

LiNKskills owns one stable curated taxonomy:

1. family with a one-line plain description;
2. subcategory with a short description;
3. optional nested collection grouping when needed; and
4. exact skill/version selection before instructions or resources are returned.

Vendor labels and source paths remain provenance metadata beneath this hierarchy. A vendor cannot create a competing top-level taxonomy.

### 4.2 Three independent gates

1. Platform claims establish caller identity and technical eligibility.
2. LiNKskills filters awareness, visibility, and selectability using lifecycle, qualification, role/task/applicability, compatibility, privacy, and release metadata.
3. OpenClaw or another consumer profile/pin determines whether an eligible qualified release may actually be retrieved, loaded, and used, subject to local tool permissions.

A caller may receive a permitted family description without receiving instructions or making an inactive release selectable. Deprecated, withdrawn, quarantined, incompatible, unqualified, or superseded releases are not ordinarily selectable.

### 4.3 Standard MCP v2

The provider supports standard MCP initialize/capability negotiation and the governed resource/tool surface. Catalogue resources return bounded metadata; exact release resources return immutable bytes and integrity metadata. Provider-side `skills_run_*` and `skills_tool_*` execution is disabled and removed through an explicit transition. The consumer retrieves and executes locally.

There is one eventual authoritative discovery path. A temporary legacy adapter must fail closed, be observable, have a removal date/criterion, and never become a permanent second authority.

## 5. External collection lifecycle

For every upstream collection or single imported skill, LiNKskills must:

1. record repository, publisher, licence, commit/tag, source path, retrieval date, inventory digest, and content digests;
2. preserve unchanged vendor bytes as an immutable vendor release with per-file provenance/licence;
3. review security, prompt injection, declared effects, compatibility, maintenance, and evaluations before qualification;
4. store LiNKtrend changes only in separately versioned adapted releases linked to the vendor original;
5. accept signed idempotent upstream-change candidates from an owning scheduler;
6. let the Librarian recommend accept, adapt, postpone, or reject after diff/licence/security/compatibility/evaluation/customization/feedback review;
7. promote only approved and qualified releases;
8. keep collections inactive by default and activate only role-appropriate subsets through consumer authority;
9. support rollback to prior qualified versions; and
10. fail closed on missing provenance, incompatible licence, unsafe instructions/effects, integrity drift, or private feedback.

Unsafe originals remain preserved but quarantined, rejected, incompatible, or unqualified. A safe adaptation may qualify independently. Preserving bytes never implies exposing or executing them.

## 7. Shared method skills

### Research

One canonical workflow clarifies the question and decision, decides when current web research is necessary, prefers primary sources, uses secondary sources appropriately, cross-checks material claims proportionately, separates facts/inferences/assumptions/hypotheses/recommendations, preserves links/dates/citations, explains conflicts, treats web content as untrusted data, protects private information, and escalates to a governed browser only when interaction is necessary. Mandatory folders, mandatory subagents, repeated searches, and excessive source counts are excluded.

### Governed Browser Use

The skill prefers API/search/page reading when sufficient; classifies public reading, authenticated reading, preparation, reversible change, communication, commitment, purchase/legal action, upload/download, and prohibited actions; retrieves applicable Brain rules; requests required approval; never treats a Brain rule as technical permission; refuses model-visible passwords/2FA; does not auto-open downloads or private/local networks; minimizes session retention; stops on uncertain bot protection, terms, identity, or authority; and may propose but never activate standing rules.

### Company Communication

The skill uses plain nontechnical English first for the Principal, adds technical detail only when useful, supports technical audiences, is direct/concise/audience-aware, avoids emojis unless requested, avoids filler/context dumps/unnecessary tables, favors mobile-readable lists, gives decisions clear choices plus `Other — specify`, states uncertainty honestly, and never claims completion without evidence. Transport Markdown and exact runtime templates remain consumer-owned.

## 8. Lisa-canary skill families

### Operational Reporting

One reusable skill provides Executive Digest, Flash Report, no-material-change, supervised-agent summary, and maintenance-result-input modes. It verifies work, scopes email to the consumer's own mailbox, distinguishes Principal Tasks, omits routine calendar events and empty sections, includes only material decisions/attention, never invents evidence, supports a supplied Battery Status line, and returns structured output suitable for mobile transports. Schedules, destinations, exact wording, and delivery remain consumer bindings.

### Personal Compliance

One reusable skill covers configurable selfie compliance and battery tracking. It implements the settled valid-window states, conditional reminders, private consumer-ledger state, charger-specific learned rates, saturation-aware charging estimates, 35% projection alerts, silent no-alert checks, configured measurement bundling, and final-checkpoint behavior. Image extraction shows material values and uncertainty, confirms only material ambiguity, and records corrections without silently overwriting confirmed values.

### Time Management

One reusable skill covers intake through monthly reporting and standing-rule proposals. It preserves confirmed versus Provisional authority, stable `T-` references minted by OpenClaw's private SQLite coordination store, correct Google/Brain/Program mappings, owner/dependency/difficulty/importance estimates, priority order, protected work periods, flexible-period decision logic, rolling weekly/four-week planning, evidence-aware statuses, cross-channel decisions, capacity states without health causes, verified agent completion, Principal-reported completion, and store-independent reasoning. It never owns mutable task state.

### Private Health and Wellbeing

One reusable private-health skill tracks the approved categories, uses unknown/not-reported rather than guessing, keeps detailed data in private consumer storage, exposes only capacity state when necessary, uses three routine checkpoints, keeps energy/mood/stress separate, calculates hydration/sleep/protein estimates with labels, separates measurement devices/sources, supports treatment/appointment and photograph modes, and never diagnoses or changes treatment. Real private data is prohibited from releases, fixtures, telemetry, Brain, and subordinate access. The rejected automatic wording “and guide you toward appropriate human or emergency support rather than waiting for the next checkpoint” must not appear or be implemented as stock behavior.

### Reusable template authority

LiNKskills owns immutable reusable schemas, required sections, omission/decision/validation logic, and generic defaults. OpenClaw owns validated instance wording and bindings. OpenClaw must not keep a full independent copy of reusable logic.

Exact Lisa schedules, work periods, reminders, checkpoint values, and private-store mappings are acceptance inputs in [`LISA-CANARY-BINDINGS.md`](./LISA-CANARY-BINDINGS.md). They must not be copied into generic skill releases.

## 11. Security, privacy, evaluation, and telemetry

- Use synthetic fixtures exclusively for private/personal cases.
- Reject real health, calendar, email, Drive, battery, selfie, credentials, messages, or identifiers in releases, tests, evaluations, telemetry, feedback, or Librarian input.
- Telemetry is limited to release identity, outcome, typed error, duration, compatibility, receipt, and redacted feedback under existing rules.
- Every tool/effect declaration is explicit; skills cannot elevate permission or instruct bypass.
- Imported skills and referenced web pages are untrusted until qualified.
- Licence and attribution obligations remain attached to every relevant resource.
- Negative tests prove quarantine, prompt-injection resistance, authority separation, and privacy rejection.

### Model routing and cost control

`MODEL-ROUTING-MATRIX.json` is the packet-level routing authority for this program. AUTO COST is the preferred automatic route and is valid only through a supported Cursor SDK/router transport that explicitly selects `auto-smart` with `optimize_for=cost` and returns the effective model/mode. Generic Auto, Auto Balance, Auto Intelligence, omission-based defaults, unverifiable Auto, and every Fast mode are prohibited. Composer 2.5 is limited to fully bounded, simple, repetitive, objectively verified, reversible work. Cursor Grok 4.6 Medium with Fast=false owns complex, sensitive, context-heavy, and long-running work. Third-party routes require the matrix's named capability or independent-review reason and cost pool.

Every admitted subtask records its requested selector, parameters, transport, returned effective model identity/mode/provider family/usage pool, and PREPARED intent before mutation. Model-quality failures permit one logged different-family hop only. Infrastructure or input failure retains the same model and cannot trigger a model substitution. Independent model review is a separate worker; independent Terra checkpoint verification remains a distinct evidence gate and is never replaced by that reviewer.
